# 鲸伴 Beta 完整使用手册

> 2026-11-02 分发范围更新：维护者已决定公开小鱼修改皮肤，源码中的 `bundled-models/DaFeiYu/` 含完整模型及来源说明，新构建将默认选择它；旧版 v0.2.0-beta.1 EXE 不因此自动更新。Live2D Core 仍需自行取得并在设置中选择；D 音色和语音权重仍不提供。历史版本的发布范围以对应版本说明为准。

适用：Windows 桌面版 `0.2.0-beta.1`。作者：澄江子。文档更新：2026-11-02。

[首页](../README.md) · [模型与服务配置](MODELS-AND-SETUP.md) · [演示配置](DEMO-CONFIG.md) · [外部接入](../integrations/README.md)

## 1. 先明确要用哪些功能

鲸伴是桌面宿主，各能力可以分开接入。不必一次装齐所有模型。建议依次完成：**显示角色 → 文字对话 → 朗读 → 语音识别 → 分享画面 → 记忆**。

| 想要的体验 | 必需准备 | 可以暂时不装 |
|---|---|---|
| 只显示可互动角色 | 完整 Live2D 模型、Cubism Core | 对话、TTS、ASR、Mem0 |
| 文字聊天 | 可用对话 API，或配置好的 DSH 插件和主会话 | ASR；不需要出声时也可不接 TTS |
| 开口朗读 | TTS 服务与可用音色 | ASR、视觉模型 |
| 语音输入 | 麦克风、ASR 服务 | 摄像头 |
| 语音通话 | 直接 API 对话、ASR、TTS、输入输出设备 | 视觉功能 |
| 看图讨论 | 支持图片的对话模型、主动附图 | ASR、摄像头；也可只分享屏幕 |
| 长期记忆 | 基础记忆或 Mem0；Mem0 还需整理模型与检索配置 | Mem0 云账户、Docker |
| 敲键盘小鱼 | 兼容 BongoCat 参数的角色、Core；高亮需对应键位图片 | 对话与语音服务 |

## 2. 下载与第一次启动

从 [Releases](https://github.com/chengjiang-zi/jingban-desktop/releases) 选择标注 Beta 的 Windows 下载。便携 EXE 可直接启动；目录包完整解压后运行 `jingban.exe`，不要单独移动 EXE 而丢掉 resources 或 DLL。GitHub 的 Download ZIP 是源码。

第一次启动会显示作者、开源免费与 Beta 说明。新安装不带演示角色、Core、语音权重、已保存音色、私人聊天和 API Key。看到需要配置模型的提示是正常情况。

源码运行和打包命令见 [首页](../README.md#从源码运行)。本地 ASR 的 Python 环境独立安装，普通便携 EXE 不会自动启动该服务；Breeze 同样需要独立运行。安装问题先按 [配置指南](MODELS-AND-SETUP.md) 排查。

## 3. 导入角色与 Cubism Core

1. 从原作者取得完整模型包，解压到固定目录。
2. 到连接设置选择 `.model3.json`。同目录引用的 `.moc3`、贴图、物理、表情和动作文件应保持原结构。
3. 选择已按官方条款取得的 Cubism Core JavaScript 文件。
4. 返回陪伴空间，确认角色可见；切换不同档位检查显示。

角色可放在任意本地目录；“复制到 models”不等于完成导入。角色库记录文件路径，导入后移动或删除原文件会导致加载失败。主界面和悬浮球共用角色库，可以从两个入口切换；聊天和记忆不因换角色自动清空。

推荐目录、模型原作者与下载入口见 [模型配置指南](MODELS-AND-SETUP.md#1-放好角色和-core)。新构建默认选择小鱼；旧 v0.2.0-beta.1 EXE 可从仓库下载皮肤后手动导入。

## 4. 桌面窗口、显示大小与互动

- 从主界面进入桌面模式，用悬浮球拖动整体位置；点击悬浮球打开菜单。
- 角色和悬浮球有独立显示开关。隐藏不等于退出，从托盘恢复主界面或桌宠。
- 四档取景用于全身、半身、近景、特写；整体缩放调整桌面上的显示尺寸。两者用途不同。
- 近景和特写会有意突出上半身或面部；想看完整角色时选择全身。
- 气泡用于显示角色回复，输入栏用于打字；按设置选择是否显示气泡。
- 鼠标跟随会驱动眼睛和头部，实际幅度由角色参数决定；不同模型的表现不同。
- 点击角色触发触摸反馈，连续点击可触发组合动作或彩蛋；不是每个模型都具备相同动作资源。

若调整后越界，先恢复全身档、降低缩放，再移动位置。多显示器和不同 DPI 仍属于需要更多反馈的 Beta 范围。

## 5. 直接 API：先验证文字，再加声音

在连接设置填写服务地址、实际模型 ID、API Key。地址保留提供方要求的版本前缀，例如 `/v1`，不要填整个 `/chat/completions` 请求路径。模型名称必须与服务方可用 ID 一致，不要照抄视频里的显示名称。

API Key 留空表示保留已经保存的密钥，不等于清除。不要把真实 Key 放进 Issue、群消息或截图。

先发一句普通文字确认能回复。若没有回复，依次检查服务地址、模型 ID、Key、额度和服务端错误。只有文字成功后，再接 TTS 和图片输入，方便判断问题出在哪一层。

聊天框旁可切换“直接 API”或“DSH 助手”。切换保留草稿并停止旧回复，不会自动偷偷换到另一家模型服务。

## 6. TTS、固定音色、播放与嘴型

TTS 是文字转语音。演示使用 Breeze-TTS-2.cpp 服务和 Q8_0 权重；它不随鲸伴下载。先在 Breeze 自带界面生成、试听、保存一个声音，再把真实音色 ID 填进鲸伴。

视频中的 `jingyu_bright_soft_d_v1` 是本机保存标识，**不是可下载的公共预设**。只填这个 ID 不会产生同样的声音。D 音色不随仓库提供，参数和声音方向见 [演示配置](DEMO-CONFIG.md#d-音色清亮中带柔和)。

| 设置 | 含义 |
|---|---|
| 流式播放 | 收到音频片段就开始播放；冷启动仍可能需要等待 |
| 整句播放 | 等待本句生成后再播，适合对连贯性更敏感的服务 |
| 固定音色 | 使用已保存声音，不是每次重新设计一个声音 |
| 音量 | 调整软件输出；还需检查系统输出设备与音量 |
| 停止 | 中止当前声音；新输入可以替换旧回复 |

嘴型按实际播放音量开合。无声时应回到闭嘴状态；这是音量驱动，不是按音素逐字对口型。emoji 会从朗读文本中过滤，聊天原文仍可保留。

兼容 TTS 需要满足当前接口和音频格式要求：接口在根地址后使用 `/v1/audio/speech`，返回所选采样率的单声道 PCM16。不能假设任何返回 MP3 的服务都能直接兼容。Breeze 配置填根地址，见 [语音配置步骤](MODELS-AND-SETUP.md#2-接入-breeze-本地语音)。

## 7. ASR 与语音通话

ASR 是语音转文字。演示使用 faster-whisper + Whisper base，CPU int8。既可以按指南装本地服务，也可换兼容识别接口。

1. 确认麦克风可用，先完成一段录音转文字。
2. 确认 TTS 能朗读，直接 API 能返回文本。
3. 开始通话，识别到完整的新发言后，系统发送文字并替换上一条回复。
4. 通话中仍可打字发送；输入新消息会打断旧回复，不需要等它说完。

“持续聆听”不等于原生全双工。当前仍是识别后分轮处理，停顿检测、ASR 和模型生成都会影响延迟。扬声器回声、真人连续发言和不同设备仍需更多测试；建议先用耳机排除自己的播放声音被重新识别的问题。

DSH 插件的自动桥接当前以文字为主，连续语音通话暂不支持外部模式。不要用 API 模式下的演示来推断 DSH 插件也支持同样流程。

## 8. 摄像头、屏幕与画面理解

开启预览只是让你看到画面，**不等于已经发给模型**。要让模型看见，需要使用支持图片的服务，并选择附加当前画面，或开启每次对话附加最新一帧。

一轮可按这个顺序验证：打开无隐私内容的测试页面 → 共享或预览 → 附加画面 → 问画面上的具体内容 → 检查回复是否正确。不要仅依据模型说“我看到了”判断链路正常。

视觉是按轮附图，不是持续视频流，也不会在没有发送时持续理解摄像头。画面发往你配置的服务，费用和处理规则由相应服务决定。关闭预览或逐轮附图后，应按实际界面状态确认共享已停止。

视频中的 Word、摄像头和聊天场景部分是动画示意，用来解释使用流程；不是软件自动读写真实 Word 文件的证明。鲸伴本身也不因能看图就获得控制所有桌面软件的能力。

## 9. 基础记忆、Mem0 与了解度

基础记忆适合先保存明确偏好。Mem0 提供可选的事实整理和检索，使用开源 SDK 与本地 SQLite，不需要 Mem0 云账户或 Docker。

启用 Mem0 前，先确保对话模型可用，再准备检索模型。默认中文检索模型约 24 MB，首次下载需要联网。事实整理默认调用已配置对话服务，也可以独立配置；**本地存储和检索不等于整理过程全离线**。

| 操作 | 结果与注意事项 |
|---|---|
| 查看、编辑 | 检查自动提取是否遗漏或过时，可手动修正 |
| 删除单条 | 移除不想保留的记忆；不会修改 DSH 原始会话 |
| 清空会话 | 保留长期记忆 |
| 删除全部本地记忆 | 清空本地记忆与共享摘录；DSH 原会话不会跟着删除 |
| 导出 | 使用 Mem0 `results` JSON；不包含密钥、原始向量或完整聊天 |
| 导入 | 接受兼容 `results` 对象或记录数组；不承诺任意第三方格式无损迁移 |
| 换对话模型 | 已保存事实保留，模型使用记忆的效果可能不同 |
| 换检索模型 | 建立独立库，在迁移面板重新生成向量；不要混用不同维度 |

了解度范围 0–100，是去重记忆的估算，可在设置中隐藏。它不衡量模型准确率或真实情感；点击角色不会刷分，离线不会扣分。外部智能体管理记忆时不擅自估分。具体计算与验证见 [验证记录](VALIDATION.md)。

## 10. DSH 插件与多对话共享记忆

插件在同一仓库内，可选安装。不用 DSH 的用户直接走 API，不需要安装插件。

完整安装命令、profile 配置和卸载方式见 [插件手册](../integrations/dsh-plugin/README.md)。高层步骤是：启动鲸伴 → 开启外部调用 → 准备一个专用 DSH 会话 → 安装插件并配置本机地址与令牌文件 → 发起绑定 → 在鲸伴本机确认主对话。

- 鲸伴输入默认发到选定的主对话，只有一个主对话。
- 其他历史会话可申请绑定，确认时决定是否纳入旧聊天、是否自动朗读。
- 已绑定会话使用共同记忆，并贡献后续用户 / 助手可见文字；原聊天记录不移动、不删除。
- 不同步未绑定会话、思考过程、工具输出或图片内容。
- 解除绑定停止后续同步，先前导入的内容仍需到记忆管理中清理。
- DSH 完整回复后才交给 TTS；TTS 可流式播放，不等于 DSH 文本逐字流式回传。
- 主会话需在 DSH 中打开；DSH 自身模型服务、权限审批和连接仍由 DSH 管理。

不需要在鲸伴重复填写 DSH 的对话 Key，但不代表不需要任何模型服务。ASR、TTS 与可选 Mem0 整理模型仍按自己的配置工作。

## 11. 不装插件的外部接入

可通过 MCP 或 HTTP 调用本机桌宠。服务仅监听 `127.0.0.1:61950`，需开启外部调用并使用界面所示令牌文件鉴权。

| 接口 | 作用 |
|---|---|
| `GET /v1/capabilities` | 查询可用能力和播放客户端状态 |
| `POST /v1/commands` | 朗读、动作、气泡、任务状态、停止 |
| `GET /v1/state` | 查询状态；completed 表示播放结束 |
| `GET /v1/inputs` | 获取发送给外部智能体的输入 |
| `GET /v1/events` | SSE 通知 |

请求体、工具名和可交给 DSH 的安装提示词见 [外部接入指南](../integrations/README.md)。不要把令牌贴进公开对话，也不要把本机接口直接开放到公网。插件面向同机 DSH，不适用于另一台电脑或不同网络容器而不做额外适配。

## 12. 敲键盘小鱼模式

在角色库导入兼容模型后切换。含 BongoCat 手部参数的角色可响应键盘 / 鼠标；具体键位高亮还需要模型提供相应键位图片，没有素材的键位不会凭空标亮。

Windows 版在角色显示期间读取即时按键 / 鼠标状态，发给本机角色窗口；不记录文本输入，不写入记忆或网络接口。关闭具体键位反馈后清除高亮，基本手部动作仍可保留。切换普通模型、隐藏全部角色或退出时，行为按实现与设置停止相应采样。

视频小鱼由澄江子基于 BongoCat 素材修改。它是同一应用中的另一种角色模式，不是第二个独立软件；小鱼修改包已在仓库公开，新构建默认包含。其独立鼠标是场景对象，不是重新绑定的握鼠标手臂。来源、修改范围和兼容性见 [项目工作与来源](WORK-AND-CREDITS.md)。

## 13. 数据、升级与退出

通过仓库启动脚本运行时通常使用 `.local`；其他启动方式以软件界面显示的数据目录为准。不要把不同启动方式的数据目录混淆。

升级前退出软件并备份自己的数据目录和自备模型。记忆可先导出作为额外备份；导出的事实 JSON 不等于完整应用备份，也不含全部聊天。模型路径引用依旧需要可用文件。

关闭主窗口通常收进托盘，不代表完全退出。从托盘选择退出后，再更换程序文件。开机启动默认关闭，本版本未完成系统重启验证。

桌面密钥使用 Windows 加密，但记忆与聊天数据仍可在本机读取；网页模式密钥只保留在进程内存。模型服务可能接收对话、识别文本、图片或记忆整理内容，取决于所选模式。

## 14. 按顺序排查

| 现象 | 优先检查 |
|---|---|
| 角色空白 | Core、模型入口、贴图相对路径，回到全身档；返回陪伴空间确认画布恢复 |
| 换角色后不见了 | 原目录是否移动、模型是否完整，先恢复缩放再加载 |
| 文字请求失败 | 服务地址、真实模型 ID、Key、额度和错误信息 |
| 看不到摄像头内容 | 预览是否只是本地显示、是否真的附图、模型是否支持图片 |
| 找不到音色 | Breeze 是否运行、音色是否保存、ID 是否属于本机服务 |
| 有文本没声音 | TTS 连接、系统和应用音量、输出设备、当前是否被停止 |
| 嘴型不动 | 音频是否正在由角色播放客户端播放，模型是否有对应口型参数 |
| ASR 不可用 | 服务是否启动、麦克风权限与设备、识别地址和模型文件 |
| 通话重复识别自己的声音 | 先用耳机排除回声，检查输入设备 |
| DSH 不回复 | 插件是否启用、令牌路径、主会话是否打开、绑定是否确认、有无等待审批 |
| DSH 图片发不出 | 自动插件当前仅桥接文字，按接入文档选择支持的途径 |
| 记忆没生效 | 记忆方式、检索准备、整理模型连接；查看实际记录，不只问模型“记得吗” |
| 小鱼没有高亮 | 是否兼容模型、是否带对应键位图、反馈开关是否开启 |
| 关闭后仍在运行 | 检查托盘，使用退出而非关闭主窗口 |

仍有问题时提供：版本号、Windows 版本、使用模式、从哪一步开始异常、可复现步骤、脱敏错误信息。日志不要附带密钥、令牌、完整记忆库或私人会话。

## 15. 范围、来源与反馈

现有验证不是所有电脑和所有服务的兼容保证。多显示器 DPI、硬件回声、长期运行和更多模型适配仍需要反馈。历史测试与已知依赖告警见 [验证记录](VALIDATION.md)。

软件代码免费开源，外部 API 可能收费；角色、Core、语音和识别模型各自遵循上游条款。下载资源入口见 [模型配置指南](MODELS-AND-SETUP.md)，演示模型与参数见 [DEMO-CONFIG.md](DEMO-CONFIG.md)，使用的上游项目见 [第三方说明](../THIRD_PARTY_NOTICES.md)。
